# 0.1 Скелет проекта

Скелет уже собран. Твоя часть: поднять всё, разобраться, как оно устроено, сделать пару доработок сборки и ответить на вопросы.

## 1. Поднять

1. `git init`, первый коммит «as is», запушить в публичный репозиторий на GitHub.
2. Сгенерировать Maven Wrapper: `mvn -N wrapper:wrapper -Dmaven=3.9.9`, закоммитить.
3. `docker compose up -d`, дождаться, что все сервисы `healthy` (`docker compose ps`).
4. `./mvnw verify` — зелёный.
5. Запустить приложение обоими способами из README и открыть `/actuator/health`. Сравни `components` в ответе.
6. `docker compose --profile tools up -d`, открыть Kafka UI на http://localhost:8090.
7. `curl -X POST localhost:8089/v1/payments` — убедиться, что мок платёжного провайдера отвечает.

## 2. Доработать сборку (сам, в ветке `task/0.1-build`)

1. **Покрытие.** Подключи JaCoCo так, чтобы на `./mvnw verify` генерировался отчёт, учитывающий **и** юнит-, **и** интеграционные тесты.
2. **Информация о сборке.** `/actuator/info` должен показывать версию артефакта, время сборки и git commit id. Подсказка: цель `build-info` у `spring-boot-maven-plugin`, `git-commit-id-maven-plugin`.
3. **Быстрый цикл.** Сделай так, чтобы можно было запустить только юнит-тесты без Docker и только интеграционные, не гоняя юнит-тесты повторно. Запиши обе команды в README.

## Критерии приёмки

- [ ] Репозиторий на GitHub, wrapper закоммичен
- [ ] `./mvnw verify` зелёный с чистого клона
- [ ] Отчёт JaCoCo в `orderflow-app/target/site/...` включает IT-тесты (проверь по `ApplicationSmokeIT`)
- [ ] `/actuator/info` отдаёт `build` и `git`
- [ ] Команды быстрого цикла в README
