# Architecture Decision Records

Одно крупное решение — один файл `NNNN-короткое-название.md`. Решения не переписываем: если передумали, пишем новый ADR со статусом «заменяет NNNN».

Эти записи потом превращаются в готовые истории для system design интервью.

## Шаблон

```markdown
# NNNN. Название

Статус: предложено | принято | заменено ADR-XXXX
Дата: YYYY-MM-DD

## Контекст
Какая проблема, какие ограничения и требования.

## Варианты
1. Вариант А — плюсы / минусы
2. Вариант Б — плюсы / минусы

## Решение
Что выбрали и почему.

## Последствия
Что становится проще, что сложнее, какие риски приняли.
```
